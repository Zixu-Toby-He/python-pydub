# IMY 转 WAV

这个项目使用 Python、`pydub` 和 `numpy`，读取简化的 IMY/iMelody 曲谱，并生成 WAV 音频。当前仓库只保留 `imy转换`，不包含之前的 `pydub制作音频` 目录。

## 安装

项目使用了 `match`/`case` 和联合类型注解，建议使用 Python 3.10 或更高版本：

```bash
pip install numpy pydub
```

当前示例输出 WAV，不需要 FFmpeg。若以后导出 MP3，仍需另外安装 FFmpeg 并加入 PATH。

## 运行

入口文件是：

```text
imy转换/转换.py
```

当前入口读取：

```text
imy转换/input/世上只有妈妈好.imy
```

并生成：

```text
imy转换/output/世上只有妈妈好.wav
```

运行：

```bash
python "imy转换/转换.py"
```

也可以修改 `转换.py` 中的输入路径、输出路径和 `演奏乐器`。

## IMY 文件格式

项目使用的是一个简化格式，不是完整的标准 iMelody 解析器。基本结构如下：

```text
BEGIN:IMELODY
VERSION:1.2
FORMAT:CLASS1.0
NAME:小星星
BEAT:120
MELODY:
c1c1g1g1a1a1g1-
f1f1e1e1d1d1c1-
END:IMELODY
```

### 音符写法

当前解析器识别的音符格式是：

```text
音名 + 一位八度数字 + 可选的 -
```

例如：

```text
c1    # C 音
g4    # G 音
a4-   # A 音的延长写法
```

普通音符和带 `-` 的音符分别由 [`imy阅读器.py`](imy转换/pyimy/imy阅读器.py) 的 `生成演奏信息()` 处理。`-` 表示该音符使用延长时长；它不是一个新的音符，也不是两个独立的起音。

`MELODY` 中的空格和换行只用于排版，读取时会被删除。因此以下写法解析结果相同：

```text
c1c1g1g1
```

```text
c1 c1 g1 g1
```

```text
c1
c1
g1
g1
```

换行不会自动表示乐句，也不会改变音符长度。真正改变当前项目音长的是音符末尾是否有 `-`。

### 节拍和间隔

`BEAT` 决定一拍的毫秒数：

```text
一拍毫秒数 = 60000 / BEAT
```

例如：

```text
BEAT:120  →  一拍 500 ms
BEAT:70   →  一拍约 857.14 ms
```

`输出()` 和 `生成演奏信息()` 默认使用 `单拍占空比=0.95`。程序会为每个音符计算一个短间隔，并把静音事件插入音符之间。当前项目支持普通音符和延长音两种时值，不支持在 IMY 文件中直接写任意的四分音符、八分音符或附点时值。

当前《世上只有妈妈好》文件的开头是：

```text
a4-g4e4g4c5a4g4a4-
```

如果按歌词顺序把第一个 `a4-` 对应“世”、第二个 `g4` 对应“上”，那么“世”会比“上”持续更久。歌词和音符之间的对应关系不是程序自动推断的，而是由曲谱编写者安排的。

## 音高

音高表定义在 [`常数.py`](imy转换/pyimy/常数.py) 中，当前使用固定频率：

```text
c = 261.63 Hz
d = 293.66 Hz
e = 329.63 Hz
f = 349.23 Hz
g = 392.00 Hz
a = 440.00 Hz
b = 493.88 Hz
```

八度通过音符后的数字计算。例如 `a4` 使用 A 的基础频率乘以相应八度比例。当前不支持升号、降号和标准 iMelody 中更复杂的八度标记。

## 音色

`输出()` 当前支持以下内置音色：

```python
"正弦波"
"方波"
"三角波"
"锯齿波"
```

例如：

```python
转换器.输出(输出路径, 演奏乐器="正弦波")
转换器.输出(输出路径, 演奏乐器="锯齿波")
```

也可以传入自定义波形函数。函数接收相位，并返回建议位于 `[-1, 1]` 的振幅：

```python
import numpy

def 我的波形(相位):
    return numpy.sin(相位)

转换器.输出(输出路径, 演奏乐器=我的波形)
```

自定义函数分支会按照音符频率生成相位，并把函数结果限制在 `[-1, 1]` 后转换为音频。每个音符仍使用读取器中设置的统一音量处理。

## DeepSeek 输出为什么不同

DeepSeek 给出的内容例如：

```text
STYLE:S1
VOLUME:V15
MELODY:a.g#c#g#d+'b.a.b.r#c#...
```

看起来也是 IMY/iMelody，但它使用的是另一种更完整或不同方言的写法。里面的 `#`、`.`、`+`、`'`、`,`、`r` 等符号通常用于升降号、时值、八度变化或休止符。

当前项目的解析规则只有：

```python
r"([a-g])(\d)(-?)"
```

所以不能直接解析 DeepSeek 输出中的这些符号。`STYLE` 和 `VOLUME` 字段当前也不会影响播放效果。若要使用那种文件，需要先把它转换成当前项目的 `c1`、`g4-` 格式，或者扩展 `imy阅读器.py` 以支持完整的 iMelody 语法。

## 当前限制

- 只支持当前文档描述的简化 IMY 音符格式。
- `STYLE`、`VOLUME` 等元数据目前会被忽略。
- 不支持 `#`、降号、休止符、复杂八度标记和任意数值时值。
- `MELODY` 换行只影响可读性，不表示分句或时值。
- 歌词和音符没有结构化关联，需要手动安排对应关系。
- 当前输出以单声部连续拼接为主，尚未实现多声部混音。
